# 다중 CAPA 결정 질문 — 이희원 / 정마나미 확인용

작성: 2026-11-10 · 상태: **전체 미결정** · 대응 문서: [다중 CAPA 계약 초안](multi_capacity_contract_draft.md)

이희원에게는 계산·모델·검증 의미를, 정마나미에게는 업무 선택·권한·비교·화면 의미를 확인한다. 양쪽 결정이 겹치는 항목은 한 사람의 답만으로 확정하지 않는다. 아래 선택지는 토론용이며 추천안/확정안이 아니다. 기존 계획 문서·Mock 값도 승인된 업무 규칙으로 간주하지 않는다.

## 1. 먼저 합의할 핵심 쟁점

| 항목 | 현재 충돌/공백 | 확인 담당 | 답변 전 고정하면 안 되는 것 |
|---|---|---|---|
| 복수 CAPA | 기존 출력은 여러 행을 수용하지만 입력·결합 정책 없음 | H-01 + N-01 | 무조건 AND, 우선순위, 더 작은 수량 한도로 대체 |
| 목적함수 | 비용절감형의 추가 조달 최소화와 잔업 금지 평준화가 다름 | H-08 + N-02 | 안별 분위수·잔업 허용·가중치·최적화 순서 |
| KPI | 기존 문서의 식과 화면의 고정 코드가 잠정적 | H-09 + N-06 | 비용/결품/충족률 산식, 비교 분모, 순위 |
| 결측 | 달력은 평일 추정, 자재 부족은 미확인 등 서로 다른 가정 | H-10 + N-03 | 0/무제한/평일/OEE=1/무료 비용 보충 |
| UNVERIFIED 승인 | 현재는 브라우저 Mock의 확인 체크만 존재 | N-04 + H-10 | 체크하면 정식 승인되는 서버 정책 |
| 비교 기준 | 같은 예측 실행이라도 안별 분위수·제약·기간이 다를 수 있음 | H-09/H-11 + N-05/N-06 | 다른 기준의 숫자를 같은 순위로 비교 |

모든 답에는 **결정 값·이유·대표 입력·예상 결과·예외·규칙 버전**을 남긴다. 구현 완료 여부는 별도로 관리한다.

## 2. 이희원에게 — 계산 규칙

### H-01. 여러 CAPA를 동시에 고를 때 무엇을 계산하나요? [선행 필수]

- 선택한 제약을 모두 만족하는 하나의 계획을 만드는지, 제약 조합별 별도 프로필을 만드는지, 강도/우선순위로 완화하는지 확인해 주세요.
- 수량·설비시간·인시를 각각 계산한 후 어떻게 feasibility에 반영하나요? 미선택 제약은 검증 범위 밖으로 남기나요?
- 라우팅의 M1/M2 대체 관계와, 수량+설비시간을 함께 적용하는 전역 선택을 별도 규칙으로 구분할 수 있나요?
- **요청 산출물:** 2제품/1공유 설비 예에서 선택 조합별 평가 행·최종 판정. N-01과 정책 ID/버전 공동 확정.

### H-02. 가용시간·달력·잔업·손실의 권위 출처는 무엇인가요? [선행 필수]

- 월 명시 예산과 달력 계산치가 모두 있을 때 어느 것을 쓰나요? 서로 다른 독립 한도인지 단순 대체 자료인지 구분 기준은 무엇인가요?
- 휴일·교대·휴게·고장·예방보전이 겹치면 어떤 구간을 한 번만 차감하나요? 정규/잔업/휴일 잔업을 어떻게 분리하나요?
- NET 시간, 실효 속도, 가동률/OEE 자료가 함께 있을 때 손실을 중복 적용하지 않을 규칙은 무엇인가요? 미제공 값을 1로 가정할 수 있나요?
- **요청 산출물:** 정상일·휴일·익일 종료 교대·겹치는 정지 구간의 손계산 예. N-08과 누락/추정 달력 정책 확인.

### H-03. 인시·설비시간과 검증 시간 단위를 어떻게 구분하나요? [선행 필수]

- 경과 2h, 작업자 3명의 6인시, 설비 2대의 4설비시간을 각각 어떤 입력으로 받나요? 이미 집계된 인시에 인원 수가 다시 곱해지는 것을 어떻게 방지하나요?
- 월별 총시간만으로 판정하나요, 일·교대별 동시 사용과 선후 공정도 검사하나요? 월 총량은 맞아도 같은 시각에 자원이 부족한 경우 판정은 무엇인가요?
- 현재 MVP에서 FEASIBLE이라고 말할 수 있는 검증 범위와 검증하지 않는 일정을 명시할 수 있나요?
- **요청 산출물:** time_basis 정의·단위 변환 조건·동시성 반례와 verification_scope 목록.

### H-04. 공정·라우팅·속도·셋업의 최소 계산 범위는 어디까지인가요? [선행 필수]

- 순차 공정만 지원하나요, 병렬 공정·대체 설비·한 공정의 동시 설비+인력·분할 생산도 지원하나요?
- run_time은 제품 1개/기준 묶음당 소요인가요? 셋업은 주문별/생산 묶음별/교체별 중 무엇이고 기준 묶음 크기는 어디서 받나요?
- 설비 속도는 대당 속도인가요, 풀 전체 속도인가요? inline 소요시간과 속도 참조를 동시에 받으면 어떻게 처리하나요?
- 라우팅/속도 버전이 월중 바뀌면 월을 나눠 계산하나요, 적용일을 정하나요? 반제품 공정·재작업은 어디까지 지원하나요?
- 수량 정수화·시간 반올림·허용 오차는 입력/계산/판정/표시 단계마다 어떻게 정하나요?
- **요청 산출물:** 지원 조합 표, 자원 소비 계수 정의, 버전 선택·반올림 규칙, 미지원 패턴 처리. N-07/N-09와 연계.

### H-05. 공유 설비·자원 풀·상하위 한도는 어떻게 연결하나요? [선행 필수]

- 개별 설비 M1과 작업장/설비 풀 상한을 함께 선택하면 같은 생산의 부하를 각각 검사하되 가용량을 더하지 않는 구조가 맞나요?
- 동일 물리 설비가 두 그룹에 있을 때, 대체 설비가 여러 제품에 쓰일 때 실제 사용량을 어떻게 한 번씩 추적하나요?
- 자원 배분은 어떤 우선순위로 하나요? 기존 초안의 product_id 순 배분을 유지할 근거가 있나요, 다른 기준/최적화가 필요한가요?
- **요청 산출물:** 제품·공정·선택 설비별 contributions와 공유 자원 합계를 대조한 예. 그룹 중복·할당 불가 처리.

### H-06. 월 생산수량 한도의 대상과 합산 기준은 무엇인가요? [선행 필수]

- 한도는 완제품 출고 가능 수량인가요, 특정 공정 통과량인가요, 라인 전체 처리량인가요? 스크랩/수율 전후 어느 수량인가요?
- 서로 다른 제품의 EA를 합칠 수 있나요? 등가 생산량을 쓴다면 제품별 환산계수와 기준 단위는 누가 제공하나요?
- 수량 한도에 이미 잔업·가동 손실이 반영돼 있나요? 시간 제약과 같은 사실을 중복 제한하는 경우도 의도한 것인가요?
- **요청 산출물:** scope·accounting_point·동일/혼합 제품 합산 규칙. 실측 라우팅 없이 시간/N을 가상 생성하는 방식의 채택 여부는 명시적으로 답변해 주세요.

### H-07. 자재 부족·안전재고·기준일의 판정은 무엇인가요? [선행 필수]

- 기존 계획 초안은 자재 부족을 조달 미확인 UNVERIFIED로 제안했지만 PoC 일부 사례는 위반으로 봤습니다. 어떤 사실이 확인돼야 VIOLATED/UNVERIFIED/SATISFIED인가요?
- 입고예정·리드타임이 없는 경우와 확인된 조달 불가를 구분하나요? BOM 월중 변경·단위 환산·다단 전개·공유 자재는 어떻게 처리하나요?
- 제품/자재 안전재고는 HARD/SOFT 중 무엇이며 어느 시점에 적용하나요? 기존 생략 기본값 0의 근거를 알 수 없을 때 어떻게 하나요?
- **요청 산출물:** 순소요·재고 이월·조달 가능성·안전재고의 입력 요구와 판정 예. N-02/N-03/N-08 공동 확인.

### H-08. 기준형·안정형·비용절감형의 목적함수는 무엇인가요? [선행 필수]

- 각 안이 다른 것은 수요 분위수, 잔업 허용, 안전재고, 생산 평준화, 최적화 목적 중 무엇인가요?
- 비용절감형은 ‘재고 활용/추가 조달 최소’인가요, ‘잔업 금지/선생산 평준화’인가요, 조합인가요?
- 결품·비용·재고·잔업을 가중합/우선순위 중 어떤 방식으로 다루나요? 가중치·페널티의 근거와 단위는 무엇인가요?
- 비용 입력이 없으면 안을 만들 수 없나요, 비용 산출만 포기하나요? 목적을 모르는 상태에서 단지 생산량을 줄인 안을 비용절감형으로 부르면 되나요?
- **요청 산출물:** plan_type별 명시적 프로필·목적/제약 구분·필수 입력. N-02의 업무 정의와 함께 확정.

### H-09. KPI 산식과 안 간 비교 기준을 확정해 주세요. [선행 필수]

- 기존 TOTAL_PRODUCTION, PLANNED_DEMAND, STOCKOUT_QTY, DEMAND_COVERAGE_P80, SAFETY_STOCK_SHORTFALL, END_INVENTORY_AT_P50, OVERTIME_HOURS, MATERIAL_SHORTAGE_ITEMS, 비용 KPI 중 무엇을 유지하나요?
- 결품은 미충족 최초 수량인가요, 월별 이월 수량 합(EA·월)인가요? 부족 자재는 고유 품목 수인가요, 품목×월 건수인가요?
- P50/P80/P90가 다른 안을 공통 분모로 비교하나요? 통화·단위·인시/설비시간·기간이 다른 KPI를 합산할 수 있나요?
- null/미산출이 있는 합계·차이·추천·비교 가능 여부를 어떻게 정하나요? 현재 ranking=null 제약을 바꿀 계획이 있나요?
- **요청 산출물:** code별 식·차원·단위·집계 범위·null 규칙·계산 버전. N-06과 표시 기준 공동 확정.

### H-10. 데이터 부족·미지원·계산 실패를 어떻게 분리하나요? [선행 필수]

- 선택한 설비시간에 속도가 없거나 일부 기간의 가용량이 없으면 요청을 거부하나요, UNVERIFIED로 안을 만들 수 있나요?
- 구조/참조 오류, 필요한 행 부재, 지원하지 않는 상세 일정, 실제 모델 오류를 어떤 status/reason으로 구분하나요?
- HARD 위반과 다른 필수 제약의 미확인이 동시에 있을 때 집계 우선순위는 무엇인가요? 필수 검증이 생략된 빈 constraints[]를 어떻게 막나요?
- **요청 산출물:** missing_input_policy·required_checks·상태 전이 표. N-03/N-04와 승인 정책까지 분리해서 확인.

### H-11. 실제 예측 execution_id와 계획 대상 범위를 어떻게 묶나요?

- 계획은 실제 UUID execution_id를 참조하고 백엔드가 저장 rows를 구성하는 방식이 맞나요? FRUN 문자열이나 임의 입력 rows를 참조 키로 사용하지 않는 데 동의하나요?
- PARTIAL 예측의 제외 제품이 계획 대상이면 어떤 상태인가요? 종속수요 반제품과 독립수요 제품의 구분에 필요한 정보는 무엇인가요?
- 예측 target_month 밖 기간·분위수가 필요한 경우 새 예측을 요구하나요? what-if 수요 배수는 동일 실행의 계획 시나리오로 보존하나요?
- **요청 산출물:** planning_scope/예측 월 coverage·PARTIAL 수용 기준·시나리오 재현 규칙. N-05와 공동 확인.

### H-12. 구현을 검증할 독립 손계산·기대 결과를 제공해 주세요.

- 최소 2제품/1공유 설비/1인력 풀의 혼합 생산, 대체 설비, 휴일/잔업, BOM·재고 부족 사례가 필요합니다.
- 각 사례의 선택 정책, 중간 부하, 한도, FEASIBLE/UNVERIFIED/INFEASIBLE 기대값과 경계값/오차를 지정해 주세요.
- 해가 없는 경우·데이터가 없는 경우·계산이 실패한 경우를 분리한 정답이 필요합니다. 성능 목표 수치는 팀 합의 없이 정하지 않습니다.
- **요청 산출물:** 원본 표본과 별개로 계산한 정답표·단위/반올림 기준·지원 범위. 기존 Fixture 일치만으로 일반화/운영 검증을 대신하지 않음.

## 3. 정마나미에게 — 업무·화면 규칙

### N-01. CAPA 선택 화면과 반드시 지켜야 하는 제약은 무엇인가요? [선행 필수]

- 사용자가 수량/작업시간/설비시간을 체크해 동시에 적용하나요, 사전 정의 프로필을 고르나요, 조건별 여러 결과를 나란히 보나요?
- 사용자가 제외하면 안 되는 필수 제약이 있나요? HARD/SOFT와 우선순위를 누가 정하고 바꿀 수 있나요?
- 수량·설비·인력·자재 중 무엇을 선택했는지와 미선택 범위를 결과에 어떻게 표시하나요?
- **결정 필요:** H-01/H-06과 선택/결합 프로필·필수 제약·권한·화면 문구. 현재 체크박스 모양만으로 계산 의미를 결정하지 않음.

### N-02. 세 계획안의 업무상 정의와 필수 입력은 무엇인가요? [선행 필수]

- ‘기준형/안정형/비용절감형’의 목적을 업무 문장으로 정의해 주세요. 수요 분위수·잔업·안전재고·목표 비용이 각각 어떻게 다른가요?
- ‘안정형=P80’, ‘비용절감형=잔업 금지’를 실제 기본값으로 채택하나요, 사용자 설정인가요? 비용 정보가 없을 때도 비용절감형 명칭을 쓸 수 있나요?
- 같은 데이터를 쓰되 서로 다른 제약을 적용한 안을 비교하려는 요구도 있나요?
- **결정 필요:** H-07/H-08/H-09와 plan_type 프로필·사용자 변경 범위·필수 비용·수요/안전재고 강도.

### N-03. 부족한 입력을 사용자에게 어떻게 처리하게 하나요? [선행 필수]

- 누락 필수 열은 기존처럼 승인 불가 오류로 유지하고, 계획 기간 일부의 자료 부재는 어떤 흐름으로 안내하나요?
- 계산 차단, 보완 요청, UNVERIFIED 검토용 계획 생성 중 어떤 경우를 허용하나요? 추정값을 쓸 수 있다면 누가 어떤 근거로 확인하나요?
- 모름/미제공/적용 안 함/명시적 0을 구분하는 문구와 시각 표시가 필요합니다. 재고 0·평일 달력·무료 비용을 자동으로 넣어도 되는지 별도 결정해 주세요.
- **결정 필요:** H-10과 결측 처리 표·수정 후 재검증 동선·부분 자료 수용 범위. 기존 승인 게이트를 우회하지 않음.

### N-04. UNVERIFIED 계획을 정식 승인할 수 있나요? [선행 필수]

- 승인 금지인가요, 특정 사유/권한에서 예외 승인 가능한가요? 가능하면 미확인 제약별 확인·사유·근거·승인자 수는 무엇인가요?
- FEASIBLE과 ‘승인됨’을 분리하고, 예외 승인이 미확인 사실을 확인된 사실로 바꾸지는 않는다는 표시가 필요한가요?
- 승인 뒤 데이터·선택·시나리오가 바뀌면 다시 승인받는 기준은 무엇인가요?
- **결정 필요:** H-10과 승인 자격/예외/재승인/이력 요구사항. 현재 Mock의 ‘감수하고 승인’ 체크는 정식 정책 근거가 아님.

### N-05. 어떤 예측 실행과 어떤 제품/기간을 계획에 사용할까요?

- 사용자가 저장된 예측을 직접 선택하나요? 자동 최신 선택을 허용하더라도 최종 선택 UUID·기준일·기간·모델·제외 제품을 언제 확인하나요?
- PARTIAL 예측에서 누락된 계획 대상 제품을 사용자에게 어떻게 안내하나요? 재예측·대상 변경·검토 중단 중 어떤 행동을 제공하나요?
- 실제 예측과 연결되지 않은 예시 계획을 지금처럼 구분할 문구는 무엇인가요?
- **결정 필요:** H-11과 실행 선택·대상/월 coverage·what-if 전제 확인 동선.

### N-06. 계획안 비교 화면의 기준과 KPI는 무엇인가요? [선행 필수]

- 비용·결품 위험·재고·잔업·병목 중 우선해서 보여줄 항목과 순서를 정해 주세요. 기존 고정 KPI 코드를 그대로 쓸지 확인이 필요합니다.
- 안별 분위수·기간·선택 CAPA가 다를 때 어떤 공통 기준을 함께 보여주나요? 다르면 비교 불가/별도 그룹/설명 표시 중 무엇인가요?
- INFEASIBLE/UNVERIFIED를 나란히 보여주는 것과 비교/추천 대상으로 인정하는 것을 구분하나요? 순위/추천이 필요한가요?
- 비용이나 KPI가 null이면 미산출/비교 제외를 어떻게 표시하나요? 없는 값을 0으로 보여주지 않는 방향을 확인해 주세요.
- **결정 필요:** H-09와 KPI 사전·단위·계산 기준 버전·비교 자격·정렬/추천 규칙.

### N-07. 공유 설비 병목과 제약별 결과를 어떻게 보여줄까요?

- 설비/인력/작업장/제품/공정/월별 한도와 사용량, 다른 제품이 차지한 기여량을 어느 수준까지 펼쳐 보여줄까요?
- 선택/미선택/자료 부족/지원하지 않음과 충족/위반/미확인을 구분하는 표식이 필요합니다. 사용자에게 어떤 의미로 설명하나요?
- 원본 파일 위치·배치 버전·환산 근거·적용 달력을 조회하는 상세 동선과 수정 책임자는 누구인가요?
- **결정 필요:** H-03/H-04/H-05와 진단 열·필터·상세 화면. 현재 타입의 누락 resource_id/source와 nullable period/unit 보완 범위.

### N-08. 근무·잔업·휴무·재고 기준일의 실제 업무 규칙은 무엇인가요?

- 공장/작업장마다 달력이 다른가요? 휴일 잔업·설비 보전·교대 인원 차이의 입력/승인 주체는 누구인가요?
- 잔업 가용량이 있어도 특정 계획안은 사용하지 못할 수 있나요? 허용 한도 변경에는 어떤 확인이 필요한가요?
- 재고가 며칠/몇 개월 지나면 오래된 것으로 보나요? 데이터 기준일과 계획 시작일이 어긋나면 어떻게 하나요?
- **결정 필요:** H-02/H-07과 달력·잔업 정책·자료 신선도·기간 경계 기준. 임의 날짜 임계값은 넣지 않음.

### N-09. CAPA 자료 등록·승인 흐름은 어떻게 구성할까요?

- 자원/공정/달력/속도/라우팅/수량 한도를 파일 여러 개로 받나요, Excel 시트로 나누나요? 실제 익명화 표본을 받을 수 있나요?
- 자원·공정 마스터 → 달력/가용량 → 속도·라우팅 → 제약 프로필처럼 참조 순서를 안내해도 되나요?
- 여러 자료 중 일부만 유효할 때 전부 반려하나요, 묶음 단위를 나누나요? 승인 뒤 버전 교체·유효기간 변경은 어떻게 요청하나요?
- **결정 필요:** 업로드 단위·참조 승인 순서·버전 교체 UX. 현행 서버는 CAPA entity 반입을 지원하지 않으므로 기존 product 파일에 임의 필드를 끼우지 않음.

### N-10. 시나리오 override와 비용 입력을 누가 확인하나요?

- 시나리오에서 바꿀 수 있는 인원·설비 수·잔업·속도·안전재고·수요 배수·단가는 무엇인가요? 승인된 원본과 가정값을 어떻게 구분하나요?
- 실제 확인 자료와 다른 가정으로 만든 안을 실제 승인 후보로 볼 수 있나요? 변경 사유·기준 버전·권한은 무엇인가요?
- 원가 자료 접근 범위, 통화/단위 표시, 미산출 비용이 있는 안의 설명은 어떻게 하나요?
- **결정 필요:** H-08/H-09와 변경 가능 필드·근거·접근 권한·시나리오 이력. 원본 승인 데이터는 덮어쓰지 않음.

### N-11. 정식 출력에 어떤 선택·판정·승인 정보를 남겨야 하나요?

- 안별 분위수, 실제 예측 execution_id, 제약 선택 목록·미적용 사유·공유 설비 부하·배치/정책 버전 중 필수 증적은 무엇인가요?
- 기존 5시트에 열을 더할지 별도 상세 시트를 만들지, 미선택과 미확인을 어떻게 표시할지 정해 주세요.
- 현재 DEMO/UNVERIFIED 출력 등급과 계획의 UNVERIFIED 판정은 다른 뜻입니다. 공식 문서 전환/배너 변경은 정식 승인·조회 구현 후 어떤 조건에서 허용하나요?
- **결정 필요:** H-09와 출력 버전·증적·승인 연계. 현재 formatter API에 새 필드를 보내거나 배너만 제거하는 방식은 채택하지 않음.

## 4. 답변 기록 양식

각 H-/N- 항목에 아래를 작성한다. 아직 답이 없으면 미결정으로 유지한다.

| 항목 | 기입 내용 |
|---|---|
| 질문 ID / 상태 | 예: H-01 / 미결정·추가 자료 필요·합의 완료 |
| 결정 내용 | 모드/값/의미를 구체적으로 기록. ‘적당히 처리’ 같은 구현자 재량 표현 피하기 |
| 적용 범위 | 기업/작업장/제품/기간/계획 유형/검증 시간 단위 |
| 근거·예외 | 자료 위치, 실측/가정 구분, 반례, 누가 확인했는지 |
| 규칙 버전·확인자·확인일 | 계산/업무 양쪽에 영향이 있으면 양쪽 확인 |
| 입출력 예시 | 필수 사실, 선택 목록, 중간 값, 최종 status/feasibility/KPI/화면 표시 |
| 남은 문제 | 추가 질문·지원하지 않는 조건·후속 버전으로 미루는 범위 |

## 5. 확정 전 보류와 확정 후 개발 순서

지금 보류할 것: CAPA를 단일 수량으로 치환하는 계산, AND/우선순위/완화 규칙, 자원 배분·셋업 최적화, 기본 잔업/평일/효율 값, 세 안의 목적함수·KPI·순위, 결측 자동 보충, UNVERIFIED 정식 승인, 새 export 필드와 정식 문서 발행. 이번 단계는 두 문서 작성뿐이며 코드·DB·Schema 작업을 시작하지 않는다.

확정 후 순서 제안:

1. 핵심 H-/N- 답변과 지원 범위·손계산 정답·화면 기준을 공동 승인한다.
2. 다중 CAPA/계획 입출력 버전을 확정하고 기존 계약과의 변환·거부 조건을 정한다.
3. 스키마·정규화·참조/기간/단위/결측 검증을 구현한다.
4. 새 데이터 등록·승인·버전 보존을 설계하고, 이후 승인받은 신규 마이그레이션/API로 연결한다.
5. 계획 순수 함수와 공유 자원·달력·자재의 독립 손계산 검증을 먼저 통과시킨다.
6. 실제 예측 execution_id·입력 digest를 고정해 계획 실행·저장·조회·동시성을 연결한다.
7. 선택/미선택/위반/미확인·비교 기준 UI와 실제 E2E를 검증한다.
8. 별도 확정한 권한·예외·재승인 규칙을 갖춘 정식 계획 승인·출력을 구현한다.
